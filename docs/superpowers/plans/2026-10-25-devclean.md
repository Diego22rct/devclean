# `devclean` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a fast, standalone Terminal UI (TUI) tool in Rust (`devclean`) that concurrently discovers regenerable build artifacts, dependencies, and caches across Node, Flutter, Rust, .NET, and Python projects in developer workspaces, calculates sizes in the background, and allows safe, interactive purging.

**Architecture:** A multi-threaded Rust CLI/TUI using `ratatui` and `crossterm`. Directory discovery runs via `jwalk` filtering on project manifest boundaries; discovered candidates stream through unbounded crossbeam channels to background worker threads calculating byte sizes and modified timestamps; the TUI event loop renders real-time updates and handles interactive navigation, sorting, multi-selection, and modal confirmation of deletions (with full `--dry-run` simulation support).

**Tech Stack:** Rust 2021, `ratatui` (0.29), `crossterm` (0.28), `jwalk` (0.8), `rayon` (1.10), `crossbeam-channel` (0.5), `clap` (4.5), `chrono` (0.4), `tempfile` (3.14).

**Spec:** `C:\Dev\tools\devclean\docs\superpowers\specs\2026-10-25-devclean-design.md`

## Global Constraints

- Standalone single binary output: `devclean.exe` with zero external runtime dependencies.
- Never delete or descend into `.git`.
- Strict contextual validation: generic directory names (`bin`, `build`, `dist`) are only flagged if they strictly match ecosystem rules and compiler output patterns.
- All interactions happen in the TUI: `--dry-run` launches the TUI with an active `[SIMULATION / DRY-RUN]` badge that simulates deletions without disk writes.
- Deduplication: Every artifact is tracked by canonical normalized path; no path is listed or counted more than once.
- Aggregation: Python `__pycache__` directories within a project are aggregated into a single line item.

## Review Focus

1. **Windows Long Paths (>260 chars)**: Deeply nested directory trees in `node_modules` or monorepos hitting `MAX_PATH` on Windows. Handled by using `dunce::canonicalize` or verbatim path prefixes (`\\?\`) so size calculation and deletion do not fail with path-not-found errors.
2. **Locked Files / Permission Denied during Deletion**: Background processes (e.g. running dev servers, IDE indexing) holding locks on files inside `node_modules` or `target`. The deleter must report partial deletion failures gracefully in the UI without crashing the event loop.
3. **Empty or Non-Existent Scan Root**: User passes a non-existent or inaccessible path as the CLI argument. Must display an immediate friendly error and exit with code 1 instead of panicking.
4. **Symlinks & Junction Points**: Directory symlinks or junctions pointing outside the project. The scanner must follow or skip without entering infinite loops.
5. **Rapid Keypresses during Modal / Background Deletion**: User spams navigation or exit keys while a deletion task is executing. Application state must lock modal input during deletion progress.
